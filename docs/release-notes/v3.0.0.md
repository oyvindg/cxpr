# cxpr 3.0.0

Breaking release for strict boolean semantics. Numeric values are no longer
truthy/falsy in boolean positions; expressions must produce `bool` where a
boolean is required.

## Added

- `<cxpr/typecheck.h>` with the shared AST typecheck pass used by tree eval,
  compiled IR, codegen, engine watches, basket folds, and host integrations.
- `<cxpr/ir.h>` as a versioned, read-only inspection API. It deliberately does
  not expose mutable IR construction or a serialized bytecode format.
- Literal lookback IR resolution for `expr[n]`. Literal and nested literal
  lookbacks now compile to `LOOKBACK_RESOLVE`; dynamic lookbacks still use the
  AST fallback.
- `cxpr_analysis.max_lookback_depth`.

## Changed

- Generated model descriptors use ABI version 3 and support bounded inventories
  of up to 64 inputs, outputs, and parameters.
- `and`, `or`, `not`, ternary conditions, `any(...)`, `all(...)`, bool eval
  entrypoints, and watch roots now require bool values.
- Typed IR `NOT` and conditional jumps require `CXPR_VALUE_BOOL` at runtime.
- Basket `any`/`all` require bool child results.

## Migration

- Replace bare numeric conditions with comparisons:
  - `entry: volume` -> `entry: volume > 0`
  - `entry: rsi(14)` -> `entry: rsi(14) > 70`
  - `active_when: 1` -> `active_when: true`
- Replace numeric `not` with an explicit comparison:
  - `not atr(14)` -> `atr(14) <= 0` or another domain-specific predicate.
- Ensure host-provided runtime flags are bound as bool values, not numeric
  `0.0`/`1.0`, when they are used with `not`, `and`, or `or`.
